# 项目运维与架构说明

## 一、网站架构

- 前端：`/www/wwwroot/Aluminum/frontend`
- 后端：`/www/wwwroot/Aluminum/backend`
- 线上静态站点：`/www/wwwroot/Aluminum/frontend/build`
- Nginx 配置：`/www/wwwroot/Aluminum/nginx配置建议.conf`

### 访问链路

- 域名访问 `lingyealu.cn`
- Nginx 直接返回 `frontend/build` 下的静态文件
- `/api/` 反代到 `127.0.0.1:8000`
- `/media/` 指向 `backend/media/`
- `/static/` 指向 `backend/staticfiles/`

### 关键结论

- 生产环境页面不是跑 `npm run dev`
- 域名实际展示内容取决于 `frontend/build`
- 修改前端源码后，必须重新 `npm run build`

## 二、前端重启方式

### 开发模式

```bash
cd /www/wwwroot/Aluminum/frontend
npm run dev
```

- 监听端口：`4001`
- 适合本地联调和快速预览
- 改源码后通常热更新，但有时需要重启

### 生产更新

```bash
cd /www/wwwroot/Aluminum/frontend
npm run build
```

- 产物输出到 `frontend/build`
- 线上域名实际读取这里的文件
- 只有 build 更新后，线上才会看到最新页面

## 三、后端重启方式

后端以当前实际运行脚本为准，常见方式：

```bash
cd /www/wwwroot/Aluminum/backend
python run_server.py
```

如果后端是后台进程或 systemd 管理，需要按当前部署方式重启对应进程。

## 四、Nginx 重载

如果修改了站点配置：

```bash
nginx -t
systemctl reload nginx
```

如果改的是静态内容，只改前端源码不够，必须先 `npm run build`。

## 五、排查顺序

1. 先确认改的是源码还是 build
2. 再确认域名是否指向这台机器
3. 再确认 Nginx 是否仍在读旧静态文件
4. 最后再看浏览器缓存或 CDN 缓存
